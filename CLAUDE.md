# leaguesapp

Amateur sports league platform for Palestine. Arabic-first, RTL. Web now, Expo mobile later.
Stack rationale lives in `docs/STACK.md` — read it only when changing the stack, not to recall it.

## Gates

- **Creative work** (new feature, component, screen, behavior change) → invoke `superpowers:brainstorming` first and stop at its approval gate. Not for lookups, explanations, typo fixes, or one-line changes — the skill costs tokens, so it earns its place only when something is being designed.
- **Any UI work** → invoke `impeccable:impeccable`. Design decisions belong in `DESIGN.md`, not in chat, so the next session inherits them instead of re-deriving them.

## Token rules

Global config already covers graphify-first and RTK. Project-specific rules only:

- Read `src/types/database.ts` (generated by `supabase gen types typescript`) to learn the schema. Never read migrations to recall a column name.
- One vertical slice per session. Auth, then teams, then fixtures — not all three.
- Server Actions, not API routes.
- No service layer, repository pattern, DTOs, or state-management library. Server Components and RLS already do that work.
- Conventional Next.js patterns only. A custom abstraction is re-read every session, forever.

## Stack

Next.js 15 App Router · TypeScript · Tailwind v4 · shadcn/ui · Supabase (Postgres, Auth, Storage, RLS) · next-intl

- Auth v1: **phone + password**. No SMS OTP — it is not free.
- Payments: **records only, admin-confirmed**. No gateway. Cash, bank transfer, WhatsApp.
- Notifications: Web Push primary. OpenWA is a fallback for reach, never for auth.

## Arabic / RTL — non-negotiable

- All user-facing copy in Arabic, Palestinian dialect. Not MSA, not translated English.
- `dir="rtl"`. Logical properties only: `ms-` `me-` `ps-` `pe-` `start` `end`. Never `ml-` `mr-` `left` `right`.
- Western digits (1, 2, 3). Local date formats.
- Strings live in next-intl message files, never hardcoded in JSX.

## Scale later, columns now

Put `sport_id`, `city_id`, and `currency` on the relevant tables from the first migration. Build no abstraction layer over them until sport #2 actually exists.

## Do not build

Payment gateway · automated venue booking · live match mode · ELO rating · transfer market · knockout tournaments · AI scheduling · a separate admin application.

Admin is role-gated routes inside the same app.

## Before claiming done

Run `npx tsc --noEmit`. Leave one assert-based check behind for any non-trivial logic.
