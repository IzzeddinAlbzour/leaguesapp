الدليل الفني الشامل لمشروع "دوريات"

ترجمة كاملة لملفات CLAUDE.md و STACK.md و leaguesapp-design.md و foundation.md بلهجة فلسطينية بلدية واضحة، مع شرح كل جدول وكل سطر كود وكل مرحلة من مراحل البناء بالتفصيل.

1. القصة والهدف

المشكلة

تنظيم دوري الحارة أو المدينة بيتم عبر جروبات واتساب وملفات إكسل. المواعيد بتتضارب، إحصائيات الأهداف بتضيع، والكابتن بعترض إن الترتيب غلط لأنه مكتوب على ورقة.

"فزنا 3-2 ومش محسوب فارق الأهداف! ومين نسي يسجل صاحب الهدف التاني بالجروب؟"

الحل

منصة إلكترونية محكمة. الكابتن بسجل فريقه، الأدمن بولد جدول المباريات بضغطة زر، والترتيب بحسب حاله تلقائياً من واقع النتائج المعتمدة بـ SQL View. مستحيل يغلط.

الإطلاق الأول: دوري جنين 7 ضد 7 كرة قدم. البنية مجهزة للتوسع لكل المدن الفلسطينية ولألعاب ثانية (سلة، طائرة).

ليش Supabase مش Firebase؟

لأن ترتيب الدوري مسألة SQL تجميعية. Firebase (Firestore) بجبرك تحسب الترتيب بالكود أو تخزن عدادات منفصلة بتتزحلق عند أي تعديل. Postgres بحسبها بكويري واحدة ومستحيل تغلط.

ليش Phone + Password مش SMS OTP؟

رسائل الـ SMS لفلسطين بتكلف $0.04–0.08 ع الرسالة + رسوم شهرية للرقم. الحل: تسجيل برقم الجوال وكلمة السر بكلفة $0. لما يصير عنا إيرادات، Supabase Auth ببدل المزود بدون ما يتأثر أي شي بالداتا بيز.

5. المحرك الثلاثي والأدوار

كل شي بالمنصة بيدور حوالين هاد المحرك:

المباريات (Fixtures) → النتائج (Results) → ترتيب الدوري (Standings)

البروفايلات، بطاقات اللاعبين، والملاعب كلها أقمار صناعية. لحد ما الترتيب يحدث حاله تلقائياً بعد مباراة حقيقية، ما في منتج.

الأدوار الأربعة:

الدورالصلاحيات
اللاعبتسجيل، استكمال البروفايل، الانضمام لفريق، استعراض الجدول والإحصائيات.
الكابتنكل صلاحيات اللاعب + إنشاء فريق، روابط دعوة واتساب، تسجيل الفريق بالدوري، إدخال وتأكيد النتيجة، طلب تأجيل.
صاحب الملعبيشوف حجوزات ملعبه ومواعيد المباريات (مؤجل لبعد MVP).
المنظم (Admin)كل شي: إنشاء دوري، توليد القرعة، تأكيد الدفعات، حسم النزاعات. (مسارات داخلية محمية بـ profiles.role).

قرارات فنية مفتاحية:

الترتيب والإحصائيات Views وليست عدادات مخزنة. العدادات المخزنة بتتزحلق لما الأدمن يعدل نتيجة غلط أو يلغي مباراة. الـ View بيعيد الحساب من المصدر كل مرة ومستحيل يغلط.
النتيجة هي المرجع؛ الأحداث هي التوزيع. home_score و away_score هم الحقيقة. match_events بيسجل مين سجل ومين صنع. مش مطلوب يتطابقوا — بدوريات الهواة حدا دايماً بينسى يسجل هداف.
قائمة الموسم منفصلة عن عضوية الفريق. team_members = الفريق الدائم. league_rosters = القائمة المعتمدة لموسم واحد. اللاعب بقدر يكون بقائمة دوري واحد بس.
قوانين الرياضة تكوين مش كود. sports فيها points_win, points_draw, allows_draw. كرة قدم، سلة، وطائرة بيختلفوا بصف (row) مش بكود.

8. مسار اعتماد النتائج

مسار محكم لمنع التلاعب وضمان نزاهة الجدول:

scheduled (مجدولة)
   │  الكابتن يدخل النتيجة والأحداث
   ▼
awaiting confirmation (بانتظار التأكيد)
   ├── الكابتن الخصم يؤكد → الأدمن يؤكد → played ✅
   ├── الكابتن الخصم يعترض → الأدمن يحسم → played ✅
   └── مرور 48 ساعة بدون رد → الأدمن يحسم → played ✅

⚠️ الترتيب بيحسب فقط المباريات بحالة played أو walkover.
   نتيجة غير مؤكدة = غير مرئية بالجدول.

9. ترتيب الدوري (SQL View)

الاستعلام اللي بيحسب الترتيب تلقائياً من واقع المباريات المكتملة:

create view standings as
with rows as (
  select league_id, home_team_id as team_id,
         home_score gf, away_score ga
    from matches where status in ('played','walkover')
  union all
  select league_id, away_team_id,
         away_score, home_score
    from matches where status in ('played','walkover')
)
select league_id, team_id,
  count(*)                              played,
  count(*) filter (where gf > ga)       won,
  count(*) filter (where gf = ga)       drawn,
  count(*) filter (where gf < ga)       lost,
  coalesce(sum(gf),0)                   goals_for,
  coalesce(sum(ga),0)                   goals_against,
  coalesce(sum(gf - ga),0)              goal_difference,
  count(*) filter (where gf > ga) * 3
  + count(*) filter (where gf = ga)     points
from rows group by league_id, team_id;

10. خوارزمية قرعة المباريات

خوارزمية دائرية (Circle Method) نقية بدون أي مكتبة خارجية. بتضمن كل فريق يلعب ضد الكل مرة وحدة ومستحيل يلعب فريق مباراتين بنفس الجولة.

11. خطة البناء (8 Slices)

كل مرحلة = جلسة عمل واحدة مركزة. المرحلة خلصت لما شرط القبول يتحقق و npx tsc --noEmit يطلع نظيف.

  • — generateFixtures

    منجز

    الخوارزمية النقية: 8 فرق بتولد 28 مباراة، كل زوج مرة وحدة، ولا فريق بيلعب مرتين بنفس الجولة.

  • Slice 0: Foundation

    شغال حالياً

    Next.js 15 + Supabase + RTL + تسجيل برقم الجوال وكلمة السر. الشرط: سجل وادخل والصفحة تطلع عربي RTL.

  • Slice 1: Profiles

    قادم

    استكمال البروفايل مع الصورة الشخصية والمركز والقدم المفضلة. الشرط: بروفايل كامل مع صورة ومحفوظ.

  • Slice 2: Teams

    قادم

    الكابتن ينشئ فريق و 6 لاعبين ينضموا برابط واتساب. الشرط: القائمة تعرض 7 لاعبين.

  • Slice 3: Leagues & Payments

    قادم

    8 فرق مسجلة، الأدمن يأكد الدفعات (كاش/ريفلكت/إيبراق)، وكلها تصير active.

  • Slice 4: Fixtures

    قادم

    توليد جدول المباريات مع تحديد الملعب وموعد الصافرة لكل مباراة.

  • Slice 5: Results & Standings ⭐

    جوهر المنتج

    إدخال النتيجة، الكابتن الثاني يأكد، الترتيب يرتب حاله فوراً. هون المنتج بيوجد فعلياً.

  • Slice 6: Stats & Player Card

    قادم

    بطاقة اللاعب (أهداف، صناعات، كروت) بأرقام حقيقية وقابلة للمشاركة.

  • Slice 7: Web Push Notifications

    قادم

    إشعارات التذكير بمواعيد المباريات والنتائج على تلفونات اللاعبين.

Slices 0-5 هم الـ MVP. كل شي بعدهم = الاحتفاظ بالمستخدمين (retention).

14. سيناريو عملي حي

رحلة الكابتن أبو خليل من جنين:

1. التسجيل — أبو خليل بفتح التطبيق ع تلفونه، بحط رقمه 0599123456 وكلمة السر وبسجل.
2. تأسيس الفريق — بعمل فريق اسمه "نشامى جنين" وبحمل اللوجو. بطلعله رابط دعوة.
3. دعوة الشباب — ببعث الرابط ع جروب الواتساب. فادي ومحمود وسامي وباقي الشباب بضغطوا وبنضموا.
4. الاشتراك بالدوري — بختار "دوري جنين للسبعات"، بحول 200 شيكل عبر Reflect، وبيرفع صورة الوصل.
5. موافقة الأدمن — المنظم بشوف الوصل بالتطبيق، بضغط "تأكيد". الفريق بصير active. بضغط "توليد الجدول" فبتنزل كل المباريات مع الملاعب والمواعيد.
6. لعب المباراة — بعد المباراة أبو خليل بفتح التطبيق وبكتب: فزنا 4-2. بسجل الهدافين: محمود (2)، أبو خليل (1)، سامي (1). الكابتن المنافس بضغط "تأكيد".
7. التحديث الفوري — بفرشة عين! الترتيب بتتحدث: نشامى جنين ع 3 نقاط بالأول، ومحمود بتصدر قائمة الهدافين. 🎉
سؤال مفتوح: أسعار الملاعب والحكام الحقيقية بجنين مش معروفة بعد. هي إعدادات الدوري (entry_fee, deposit_amount) مش ثوابت بالكود، فالتنفيذ مش متوقف عليها. الأرقام لازم تتحط قبل ما يفتح دوري حقيقي.
